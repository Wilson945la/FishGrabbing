## 修复 2048 对决模式"总是平局"的 Bug

### 问题根因
`Game2048DuelGame.handleGameOver()` 解析服务端返回的对决结果时，用 `resultsData.split(",")` 按逗号切分玩家，再 `split(":")` 取 4 段。但服务端实际格式（与 Minesweeper/Tetris 一致）是用 `;` 分隔玩家、每个玩家为 `name,result:time:score`。因此 2048 的切分方式让每条记录都因 `parts.length < 4` 被丢弃，`playerScores` 为空 → `winner` 恒为 null → 对话框永远显示"平局！"。

### 修复内容（Game2048DuelGame.java）
1. 解析改为 `resultsData.split(";")` → 每条 `split(",", 2)` 得 name 与 `result:time:score` → 再 `split(":")` 取 result/time/score（对齐服务端）。
2. 增加真正的平局判定：最高分若被多人并列（`bestCount > 1`），`winner` 置 null 显示"平局！"，而非默认把第一个玩家判为胜者。

### 编译
客户端 `javac -d /tmp/jc_out src/*.java` 通过（EXIT=0）。

## 为 2048 经典模式加入滑动/合并/弹入动画

### 问题
经典 `Game2048` 棋盘用 `GridLayout` + 固定 `JLabel[][]`，每次移动在 `updateUI()` 里瞬间改文字/颜色，方块"瞬移"，毫无过渡，手感生硬。

### 重构方案（Game2048.java 重写渲染层）
- 新增 `Tile` 内部类：携带 `value / r / c / fromR / fromC / merged / spawned`，用"来源格→目标格"做插值。
- 棋盘改为自定义 `BoardPanel extends JPanel`，`paintComponent` 用 `Graphics2D` 圆角矩形绘制每个方块（开启 ANTIALIASING）。
- 移动时 `doMove(dir)` 记录每个方块起点，按方向收集行/列、滑动+合并，合并出的"被吞"方块进入 `animConsumed` 列表滑入目标格后消失。
- 动画由 `javax.swing.Timer`（12ms/帧）驱动：`animProgress` 0→1，前 62% 为滑动（easeOut 插值像素位置），后 38% 为弹出（合并块 `1+0.18*sin` 回弹、新块 `pp*1.15` 放大弹入）。滑动结束补生成一个新方块。
- 输入在 `animating` 期间锁住，避免动画叠加。`import java.awt.*` 会引入 `java.awt.List` 与 `java.util.List` 冲突，已加 `import java.util.List;` 单类型 import 解决。
- 同时修了一个潜在 bug：原 SOUTH 区域被覆盖导致提示文字不显示，现合并为 hint+按钮的 south 面板。
